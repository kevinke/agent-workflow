# TICKET-007: Dogfood E2E Regression Test + CI

Type: task
Status: resolved
Blocked by: none

## Goal

Give the kit its first end-to-end dogfood regression net. Round 1 (TICKET-001..006) verified units; this ticket verifies the workflow as a whole the way a target repo would use it: install the kit into a throwaway repo via the real CLI, walk one ticket through the entire phase machine, and assert the validate gate at every phase boundary. Fixed as a script (not re-generated by an LLM each time) so regression is one command, and wired into CI so it runs automatically.

## Decisions (recorded here, no new spec round needed)

Behavior under test is already specified (spec §9, ADR-0002, STATE_SCHEMA.md, PROTOCOL.md). Only decision-level points:

1. **E2E test lives at `scripts/ai-workflow/tests/test_dogfood.py`** — stdlib `unittest`, same runner as TICKET-006. It drives the real CLI (`python main.py init|status|validate`) via subprocess so the user-facing surface is tested, not just library calls.
2. **Ticket state is scaffolded from the installed template** — parsed by the kit's own parser and saved through its own state module (template → parser → save round-trip).
3. **Git commit discipline is tested when git is available** — phase-boundary commits must carry the `ai-workflow(<ticket-id>):` prefix; identity is passed via env vars, never touching git config.
4. **CI: `.github/workflows/ci.yml`** — matrix over ubuntu + windows, one command from `scripts/ai-workflow/`. Zero-dependency means no pip install step is needed (ADR-0002).

## Found and fixed (the dogfood payoff)

The new E2E test went red immediately and exposed a real protocol bug: the terminal phase `done` could never validate clean. `done` requires clearing `next_action`, but an emptied block leaves `role: None`, which `validate` flagged as `illegal next_action.role None` — so no ticket could ever reach a valid done state. Fixed in `validate.py`: only check the role enum when a next action actually exists (`has_next` gates the role check). A regression unit test (`test_done_with_cleared_next_action_passes`) locks it down.

## Definition of done

- `test_dogfood.py` passes; full suite green (67 tests) with one command on Windows.
- CI workflow added; the whole suite runs on push/PR on GitHub-hosted runners.
