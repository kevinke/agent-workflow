# HARDEN-011: Isolated Reviewer and Guarded Publication Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Confine reviewer execution to an identified disposable repository and publish its exact verdict only while the live code and inputs still match the captured baseline.

**Architecture:** A trusted coordinator prepares an independent clone and launches the entire local verifier process under a tested host boundary. Supervisor-owned identities and execution receipts stay outside verifier write scope. Extend the existing `set-review` command with a guarded candidate-publication mode; preserve legacy historical bindings without assigning them isolation evidence.

**Tech Stack:** Python 3 stdlib, Git, unittest; optional existing Linux `bubblewrap` executable for the first supported host profile. No package installation, new permission service or model dispatcher.

**Spec:** [C10 and testing decisions](../../../.scratch/decision-scout-hardening/spec.md#c10--isolated-reviewer-verification-and-guarded-publication-harden-011), [authoritative procedure](../../../.ai/workflow/PROTOCOL.md), [report contract](../../../.ai/workflow/ARTIFACTS.md).

**Ticket:** [HARDEN-011](../../../.scratch/decision-scout-hardening/issues/11-isolated-reviewer-publication.md). **Blocked by:** [010](2026-10-09-harden-10.md). **Sequence:** complete before the [009 pilot](2026-10-08-harden-09.md). This plan does not claim runtime enforcement is already implemented.

## Global Constraints

- Keep `workflow_version: 2`, `schema_version: 1`, Python 3 stdlib only and the existing restricted YAML parser.
- Keep v1 Ticket behavior and historical pilot completion unchanged.
- Keep v2 SHA-256 over original artifact bytes; do not normalize line endings before hashing.
- Protocol and artifact contracts own semantic rules; Skills and adapters point to them.
- Structural validation establishes conformance, not the truth of natural-language claims or model seniority.

One implementation writer owns all files below. Do not launch a model session, change host/global settings or edit live code to test denial. The coordinator and publisher are trusted; this is not authentication against a malicious coordinator. Existing advisory claims do not serialize arbitrary external writers.

## Frozen boundary and compatibility decisions

Initial profile `linux-bwrap-v1` supports **local command-based verifier sessions** with all child execution inside the namespace. It uses an installed `bwrap`; absent binary, denied namespace creation, unsupported runtime layout, Git submodules or unrepresentable input scope produce a named blocker. A 2026-10-09 disposable WSL experiment demonstrated EROFS on a read-only sentinel and successful snapshot writes; implementation must repeat it through its own entry point. This experiment did not test any model/Harness adapter.

Mount only read-only `/usr` and required runtime symlinks, private `/proc` and `/dev`, temporary `/tmp`/HOME, read-only declared inputs, writable `/snapshot` and `/scratch`. Clear inherited environment, Git overrides and descriptors; use `--unshare-all`, `--new-session`, `--die-with-parent`, no host sockets/WSL interoperability, no network or permission fallback. Baseline network/package provisioning is a coordinator prerequisite, not automatic sandbox weakening. Every actual verifier runs under this boundary, including commands reading model output; an unconstrained outer reviewer with live shell/MCP write access cannot claim support merely by sandboxing its tests.

Codex Desktop/MCP and native Windows sessions are **unsupported until their actual host tool-write restriction is separately demonstrated**. The existing Windows launch runbook does not establish that restriction. Do not claim a live adapter is supported from helper/mock tests; 009 must use a genuinely supported adapter or remain blocked.

Legacy reports without provenance retain the existing historical `set-review`/binding behavior. Reports containing the new reserved provenance section require guarded publication; ordinary `set-review` must reject them without `--review-context`. New reviewer entry points always use the guarded path. Existing consumers still check currentness; they never infer isolation for old reports. No new State field or Review Metadata version.

## Review Focus

- A copy/shared-Git worktree or escaping symlink is not isolation: `test_snapshot_scope_and_metadata` (Task 1).
- A sandbox that launches but permits live writes is unsupported: actual `test_boundary_denies_live_and_allows_snapshot` and `test_unavailable_boundary_is_closed` (Task 2).
- Checkout EOL conversion must not invalidate raw Plan/input hashes: `test_distinct_eol_manifests_and_raw_inputs` (Task 1).
- Probe success cannot erase a failing baseline or invent execution evidence: `test_provenance_matches_receipts` (Task 3).
- A rejected or interrupted publication must preserve existing records and phase: `test_publication_drift_and_recovery` (Task 3).
