# HARDEN-006: Durable v2 artifact transport and archives Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Another checkout or an explicit archive preserves the exact v2 bound bytes, including mixed line endings and external Plans.

**Architecture:** Protect bounded work-artifact paths from Git text conversion and expose external-Plan conflicts without changing hash semantics. An explicit ZIP exporter validates current bindings and stores raw bytes plus manifest; the same writer packages already verified historical pilot bytes.

**Tech Stack:** Python 3 stdlib, unittest, restricted YAML/Markdown and Git; real Harness sessions only in HARDEN-009.

**Spec:** [supplemental spec](../../../.scratch/decision-scout-hardening/spec.md), contracts C6.

**Ticket:** [06](../../../.scratch/decision-scout-hardening/issues/06-durable-artifact-transport.md). **Blocked by:** 01.

## Global Constraints

- Keep `workflow_version: 2`, `schema_version: 1`, Python 3 stdlib only and the existing restricted YAML parser.
- Keep v1 Ticket behavior and historical pilot completion unchanged.
- Keep v2 SHA-256 over original artifact bytes; do not normalize line endings before hashing.
- Protocol and artifact contracts own semantic rules; Skills and adapters point to them.
- Structural validation establishes conformance, not the truth of natural-language claims or model seniority.

All commands run from the kit repository root unless explicitly inside a disposable target. Modify only the listed write set and preserve others' edits. Exact shared interfaces and final integration are in the [master plan](2026-10-08-scout-hardening.md). This document is a pending plan, not an executed test record.
