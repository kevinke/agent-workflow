# Live Model and Harness Pilot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Observe whether cheap scouting and structured cross-Harness handoff reduce repeated exploration while retaining correctness.

**Architecture:** Run two bounded tasks against the released workflow in a disposable target. Preserve actual role outputs and measurements; assess report quality independently of CLI validity.

**Tech Stack:** Released ai-workflow CLI, Git, actual available model/Harness sessions, local Markdown records.

**Spec:** [Feature spec](../../../.scratch/decision-scout-port/spec.md), Ticket SCOUT-008. **Blocked by:** 07.

## Global Constraints

Read [the common plan](2026-10-07-decision-scout-handoff.md).
"Structural validity is not proof that acceptance criteria passed."
Use an actual inexpensive Scout and senior decision roles; at least one handoff
must cross two actual Harnesses without inherited sender conversation.
Unavailable token/cost data are UNKNOWN. Simulation does not satisfy this Ticket.

## Review Focus

Check actual model availability, real independent receiver context, anchor
correctness, targeted rereads versus repeated survey, and missing usage telemetry.
No assumed provider prices, fabricated savings or automatic external messaging.

**Interfaces:**
- Consumes: released init/start/resume/gate/Plan/review commands and persisted artifacts.
- Produces: runbook with task briefs, available model/Harness identities, capability
  checks, clean-context receiving prompt, artifact locations and measurement fields.
- Run records use Task, Role, Model, Harness, Start/end, Tool activity, Usage,
  Input/output artifacts, Repeated exploration, Targeted verification and Outcome.

- [ ] **Step 1: Define the two observable tasks.**
  In a disposable target copy the fixture: bug expects read after changing config
  to return its new value; feature adds reload(config) with specified replacement
  behavior. Use separate branches/Tickets to avoid bug/feature interference.
  Record reproduction/test commands and expected outputs before model work.
- [ ] **Step 2: Record prerequisite results.**
  Name actual available cheap/senior models and two Harnesses, tool access and
  transcript/usage availability. Run `ai-workflow --help` and `git --version` in
  each intended target environment. Expected CLI commands from 07 and working Git.
  Missing required access leaves the pilot pending with an explicit blocker.
- [ ] **Step 3: Write role prompts and measurement protocol.**
  Scout receives task/DQs and writes anchored facts. Senior receives reports plus
  resume, records targeted verification and any repeated survey. Executor consumes
  registered contracts; Reviewer starts an independent context. Receiving Harness
  gets repo/Ticket/resume and referenced artifacts, not the sender's conversation.
  Count observed tool actions by role and label unavailable usage UNKNOWN; only
  compare cost/savings when a comparable measured baseline actually exists.
- [ ] **Step 4: Review runbook completeness and commit.**
  A reader must be able to reproduce both expected task behaviors, identify each
  real session and find every output. Report remains pending; no synthetic pass.
  Commit: `ai-workflow(SCOUT-008): prepare measured live handoff pilot`.

### Task 2: Actual runs, anchor audit and findings

**Files:**
- Modify: .scratch/decision-scout-port/pilot/report.md and runbook.md.
- Create: .scratch/decision-scout-port/pilot/bug/ and feature/ with copied actual
  State, Evidence, audit, decision, Plan, Progress, Handoff and Review records.
- Modify: .scratch/decision-scout-port/issues/08-live-model-harness-pilot.md, tickets.md.

**Interfaces:**
- Produces: evidence-backed report with actual session IDs/identities, artifact
  links, observed correctness/rework and effort data; no new production API.
- Failures are measured outcomes. Missing real model pairing/Harness switch is
  an unmet prerequisite, not a successful simulated outcome.

- [ ] **Step 1: Run the bug through actual role sessions.**
  Follow the runbook and persist each output. Cross Harnesses on the planned
  handoff and record receiver inputs and first resumed action. Record escalation,
  missing facts, rework and actual acceptance verification, including failures.
- [ ] **Step 2: Run the feature with the same recording protocol.**
  Use its separate starting branch and clean receiving context. Do not fill in
  expected facts or tool counts on behalf of either model.
- [ ] **Step 3: Audit pivotal report facts and final behavior.**
  At each reported commit inspect named file/line/symbol or config key, reproduce
  runtime claims and check negative-search scope. Record incorrect/missing anchors
  separately from CLI contract failures. Run each runbook verification command;
  compare actual output/exit to its declared expectation.
- [ ] **Step 4: Write findings with practical limits.**
  Report repeated broad exploration, useful targeted rereads, gaps, clarification,
  rework, elapsed time and available usage by role. Recommend concrete Scout/task
  sizing changes only when supported by the observations; create separate follow-up
  Tickets for fixes. Never infer monetary savings from tool-call count alone.
- [ ] **Step 5: Review completion evidence and commit.**
  Both task records and an actual cross-Harness handoff must be present before
  marking this Ticket complete. If prerequisites were missing, preserve pending
  status and blocker. Commit actual records:
  `ai-workflow(SCOUT-008): record live model and harness findings`.

**Done:** Actual observed evidence supports a decision about Scout/handoff value.
